Overview
What is the Vidhan Bhavan MLS Portal?
The Maharashtra Legislature Secretariat (MLS) is the administrative body governing Maharashtra's bicameral legislature — the Vidhan Sabha (288 elected MLAs) and the Vidhan Parishad (78 members). The existing website, mls.org.in, had served the institution since the early 2000s. By 2023 it had become a liability: inaccessible to new users, impossible to update without developer involvement, and entirely in Marathi with no English or bilingual support.

I was brought in by Hands in Technology as the lead UI/UX designer to redesign both the public-facing portal and build a completely new internal admin dashboard from scratch — covering everything from member management to session calendars, debates archives, and a role-based access control system.

User Research

Two very different users, one system

Through stakeholder interviews and contextual research, I identified two primary user groups with completely different mental models and needs.

Key insight from research: Admin staff were the biggest bottleneck. They had to email developers for every content update — adding a member, changing session dates, updating FAQ answers. Building a self-service admin dashboard was not optional; it was the core requirement that would determine whether the new portal could be maintained long-term.

Site map
A structured information architecture for the MLS Portal (Vidhan Bhavan), separating public-facing modules — Members, Houses, Debates, Session Calendar, Vidhan Mandal, and Library — from a secured admin dashboard with role-based access control, content management, and MIS reporting for internal staff.

Landing Page

The citizen-facing portal

The public website needed to serve citizens who may have never interacted with a government digital platform before. I prioritised trust signals (official branding, accessibility controls, government logo), discoverability (prominent search, clear nav), and bilingual access.

Landing Page

The homepage establishes trust immediately — official logo, government colour palette (saffron/green/white), hero section with the iconic Vidhan Bhavan building, and a clean 6-item navigation. Below the fold: Vidhan Sabha + Parishad overview cards, photo gallery, important external links, and latest news.

Login & Authentication

The login screen supports multiple user types (citizen, admin staff, department heads) through a single clean interface — email, password, and a user type selector. OTP verification adds security without overwhelming complexity. The building imagery in the background reinforces institutional identity.

Member Profiles & Houses

One of the most-used features. Citizens and journalists frequently need to look up MLAs — their party, constituency, photo, contact, and voting history. I designed rich member cards with photo, party badge, and seat data, plus a doughnut chart showing composition of each house. The advanced filter allows search by party, constituency, and name.

User Profile & Document Access

Logged-in users can request access to restricted legislative documents. I designed a simple profile section — basic info, request for access form, request information status, and downloadable documents — keeping the experience within the same portal rather than redirecting to external systems.

Admin Dashboard
The internal control panel — 19 modules
The admin dashboard was invisible to citizens but critical to the portal's sustainability. Without it, the new website would face the same problem as the old one: updates require a developer. I designed a full CMS + management system so secretariat staff could run the portal themselves.
Member Management — Add & View
Admin staff can add members with full biographical data — department, name, email, designation, bio data, images/videos, party, education, marital status, date of birth. The form is long but logically grouped: account info first, then bio data as a clearly labelled second section. The View Member screen shows all member data in a clean tabular list with edit/delete actions.
CMS — Content Management
Staff can add and update all public website content — homepage banners, About Us copy, FAQs, Vidhanmandal section content (Rajyapal, Vidhan Sabha, Vidhan Parishad, Sachiv, Ministers) — without touching code. Each content type has its own Add/View pair of screens following a consistent form pattern.
Design Decisions
Key decisions and why
Colour system — saffron/green/white/navy:
Government portal design must feel official. I used the Indian tricolour palette (saffron header bar, green navigation, white content areas) as the primary system, with navy as the admin dashboard anchor. This immediately signals legitimacy to citizens who expect government sites to feel institutional, not startup-like.
Single sidebar for all 19 admin modules:
I chose a persistent left sidebar with collapsible sub-items over a multi-page navigation or top tabs. Government admin users are often not tech-savvy — they need to always see where they are in the system. The sidebar keeps context visible at all times.
Debates — progressive disclosure filter:
With 6,000+ records, showing all filter options upfront would overwhelm users. I used a "More Options" pattern — simple filters by default, advanced filters on request. This kept the default state clean while serving power users (journalists, researchers) who need granular control.
RBAC as a matrix, not a list:
The obvious approach for role management is a list of users with a dropdown per permission. I chose a matrix table instead — users as rows, permission types as columns, checkboxes at intersections. This makes it possible for a Super Admin to audit all permissions at a glance and spot gaps or conflicts instantly.
Reflection
What I would do differently
Given more time and access, I would have added three things:
Usability testing with actual citizens
we tested internally with stakeholders, but real usability testing with Marathi-speaking citizens would have surfaced friction points we couldn't anticipate from within the team.
Accessibility audit
government sites should meet WCAG 2.1 AA. The design accounts for contrast and font sizing, but a formal audit with screen reader testing would strengthen it further, especially for an audience that includes elderly citizens and government officials.
MIS Report dashboard visualisation
the MIS Report module was scoped but the data visualisation depth was limited by timeline. A richer analytics layer would help department heads understand usage patterns and make informed content decisions.
